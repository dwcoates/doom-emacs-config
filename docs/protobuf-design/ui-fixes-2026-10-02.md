# UI fixes batch (2026-10-02)

Owner requests that needed contract changes; the rest of the batch (wifi toggle
visuals, webview cursor, roster hover target, merged-row styling, discard-input
history, topbar summary prompt and cadence) is implementation only.

## Landed changes

1. **Topbar fast mode dropped** (`frontend.v1.TopbarView.fast_mode`, tag 10,
   RETIRED; `TopbarFastMode*` messages deleted — nothing else referenced them).
   WHY: owner "let's drop the 'fast' entry in the topbar". Consequences: the
   daemon's topbar resolver stops resolving it; the webapp drops the cell.
2. **Folded section counts** (`frontend.v1.RosterSectionHeader.count` =
   `RosterSectionCount { uint32 workspaces }`, always set). Drawn as "(N)" when
   the section is folded, smaller than the label, in the label's color; the
   repo sections and Recently Merged share this header. WHY: owner request.
   The count is resolved by the daemon (rows incl. nested family); fold state
   stays webview-local, so the client shows/hides it by its own fold.
   Merged rows' grey/no-dot styling is the webapp's rendering of the existing
   `merged` status arm — no contract change.
3. **Feed links open files** (`agentrepl.v1.OpenInEditorRequest.target.feed_link`
   = `OpenInEditorFeedLink { href, source_row }`; error arm
   `link_unresolved` = `OpenInEditorLinkUnresolved { href }`;
   `conversation.v1.PromptOrigin.PROMPT_ORIGIN_LINK_UNRESOLVED = 30`).
   Resolution is the DAEMON's (absolute; dir-part relative to worktree root;
   bare name → `<worktree>/modules/app/agent-repl/<name>`, then
   `<git root>/<name>`), relayed to Emacs's one editor-popup path exactly like
   `workspace_file`. Unresolved: transient footer activity line "unknown file
   <name>" (no status change) AND a non-interrupting prompt quoting the source
   bubble asking which file was meant and proposing agent-repl changes (avoid
   ambiguous links, or add a resolution fallback — pointing at the resolver
   code), offering to make the change.
