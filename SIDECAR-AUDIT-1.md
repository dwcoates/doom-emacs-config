## Teamlead rulings (binding)
R-S1 write_id digests FILE_ID (dev:inode), never the path: sha256("shim-claude-sidecar|"+file_id+"|"+offset+"|"+discriminator). A renamed file re-read from its cursor mints identical write_ids; AGENTS.md updated; the store's absorption then holds across renames. (Override of the planning doc's "path" detail — reason: rename-proof cursors and replay absorption must agree.)
R-S2 Refusal kinds: `storage_failure` → the existing suspend/recover-cursors/rescan cycle (retry can help). `invalid_request{field}` → a PRODUCER DEFECT: one ERROR record (field, write_ids, path, offset), that FILE's tailer is parked (no further reads of it until restart; its cursor stays where the store has it), every other file continues; never a tight identical replay loop. A kind-less failure from a store is itself logged at ERROR as a contract violation and treated as storage_failure.
R-S3 The boot rewind targets the last REAL user prompt: a `user` record carrying prose that is neither a compaction summary (the isCompactSummary shape) nor a tool_result carrier; keep-alive prompts DO count as turn starts. The harness helper turnStartOffsetAtOrBefore follows the same rule.
R-S4 a* spools convert through the subagent-transcript converter with agent id = the spawning call's tool_use_id (owner map); w* spools land as vendor_specific{kind "spool/workflow"} residue keyed residue:file:<path>:<offset>. Both pinned.
R-S5 The fake store gains the real store's envelope validation and `kind` arms; subjects that can run against the real store prefer it.
R-S6 Every critique's subject is added unless a ruling reshapes it; every helper defect fixed; brittle subjects (19–21) rewritten to structural waits; logging subjects assert the contract's full field set.
