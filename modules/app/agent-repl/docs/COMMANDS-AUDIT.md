# agent-repl commands and keybindings: audit

Every interactive agent-repl command, with the binding it has today. This is
the working inventory for the Emacs-bindings design: it is grouped into
fine-grained types so a wide, shallow key hierarchy can be built over it.

Scope: every `(interactive)` definition in `lisp/*.el` and `config.el`
(tests excluded), including the commands generated by macros. 105 named
commands, 34 generated diff-scope commands, and 9 generated tab-slot commands.

## How to read the tables

- **Evil key** is the binding today. `SPC` keys are Doom leader keys.
- **Emacs mode** says what the binding does in evil's emacs state or in Doom
  without evil, today:
  - `works` means the binding sits in a plain keymap or a state-independent
    place, so it fires in every mode.
  - `leader` means it is reachable under Doom's alternative leader (`M-SPC` in
    emacs state, `C-c` without evil). Without evil, Doom's leader tree is laid
    out differently (git is `C-c v`, workspaces `C-c w`), so the same suffix
    lands in the wrong subject area.
  - `missing` means it is bound only in evil normal or insert state.
  - `-` means the command has no binding.
- **Context** is where the binding applies: `global`, `leader`, or the mode or
  buffer whose keymap holds it.

Findings are collected at the end, in "Audit findings".

## Audit findings

1. **Emacs mode is missing 13 bindings.** Every row marked `missing` above is
   bound only in evil normal or insert state.
2. **The leader keys land in the wrong subject areas without evil.** Doom's
   non-evil leader tree puts git under `C-c v` and workspaces under `C-c w`,
   so `SPC g g` and `SPC TAB n` have no matching place there.
3. **Twenty-six commands have no binding.** They are the rows marked `-`,
   apart from the internal `agent-repl--send` and the
   `agent-repl-switch-to-workspace` the generated slot commands call.
   Notable ones:
   - The whole `agent-repl-update-pr-diff-SCOPE` family.
   - `agent-repl-deploy`, `agent-repl-runtime-restart` and the three
     `agent-repl-frontend-daemon-*` commands.
   - `agent-repl-send-with-metaprompt` and `agent-repl-send-and-hide`.
4. **Bound commands with private names.** `agent-repl--history-prev` and
   `agent-repl--history-next` are bound to `<up>`/`<down>`, but the `--`
   marks them as internal. `agent-repl--send` is interactive too.
5. **Commands that may overlap.** These need a ruling on whether each is still
   distinct:
   - `agent-repl-kill` and `agent-repl-kill-workspace`.
   - `agent-repl-restart`, `agent-repl-restart-workspace`,
     `agent-repl-frontend-daemon-restart` and `agent-repl-runtime-restart`.
   - `agent-repl-version` and `agent-repl-print-git-branch`.
6. **Stale keys in docstrings.** `agent-repl-close-workspace` names `SPC j x`,
   but it is bound to `SPC j d` (`SPC j x` is `agent-repl-kill-workspace`).
7. **`SPC j` mixes unrelated types at one level.** Its top level holds
   workspace lifecycle (`d`, `x`, `X`), logging (`D`, `L`, `V`), PR prompts
   (`r`, `b`, `P`), machine settings (`w`), notes (`n`) and config
   development (`R`) side by side.
8. **Bindings are spread across eight files.** `keybindings.el`, `input.el`,
   `clipboard-image.el`, `popup.el`, `frontend.el`, `core.el`, `magit.el`
   and `open-progress.el` each bind keys their own way.
