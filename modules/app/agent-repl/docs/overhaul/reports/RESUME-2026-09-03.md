## The sandbox (containerised Emacs)

`modules/app/agent-repl/e2e/sandbox/` — Dockerfile + `bin/e2e-sandbox.sh`
(verbs: build, run [--dir <module-rel>], shell, preflight), pins.env, minimal
Doom profile. Docker IS running on the host now. The image builds and
verifies (`verify_image` probes emacs/node/go/script/doom + baked doom sync);
staging is an enumerated 2244-file / 55M set (NOT the 19G checkout); HOME and
/tmp are tmpfs, the repo mount is read-only and probe-verified; `--network
none` at run time. The daemon's whole unit suite passes inside it (47 pkgs).

BLOCKER: the image's Emacs was Debian 28.2, but interactive Doom requires
>= 29.1, so early-init aborts and no readiness stamp is written. USER RULING:
the image must build Emacs FROM SOURCE at the user's exact version —
**30.2, upstream commit 636f166cfc86** (host build date 2026-05-21) — WITH
XWIDGETS (the webapp panel is xwidget-webkit; a build without it does not
work). Host configure options:
`--with-native-compilation=aot --with-tree-sitter --with-modules --with-gnutls
--with-xml2 --with-ns --with-xwidgets --disable-gc-mark-trace`,
`CFLAGS='-O3 -march=native -DFD_SETSIZE=10000 -DDARWIN_UNLIMITED_SELECT'`.
Linux adaptation: `--with-pgtk` (or gtk3) + webkit2gtk instead of `--with-ns`;
DROP `-march=native` (no host-tuned images) and DARWIN_UNLIMITED_SELECT; keep
the rest. verify_image must fail loudly if xwidgets or native-comp are
missing. An xwidget scenario also needs a headless display (Xvfb) — the
harness affordance for a GUI frame is NOT built.
