## Deliverables (`src/topbar/`, `src/login/`; tests `test/topbar/`, `test/login/`)

1. `topbar.ts` — `mountTopbar(host, ctx, deps)`: `watchStream(WatchTopbar{workspace})` → `drawTopbarView` whole on every push; local reveal state (which reveal is open) survives pushes; every reveal renders BELOW the strip inside `host`'s reveal layer, absolutely positioned under its anchor and CLAMPED to the viewport (write `clampReveal(anchorRect, revealRect, viewport)` in `src/topbar/clamp.ts` with tests); a click outside or Escape closes reveals.

2. `strip.ts` — left tight: `drawTopbarAccount` (`logged_in` → the email; `logged_out` → "logged out" in the WARNING state — orange — and clicking it calls `deps.openLogin()`; clicking a logged-in account shows the session line reveal), `drawTopbarConnectivity` (glyph verbatim, `title` as tooltip, tone class `tone-<tone>` from the vocabulary names none|blue|teal|green); center: `drawTopbarTitle` flexing; right tight: `drawTopbarModelSelector` (button shows the selected option's `display_name`, or the placeholder "model" when unset; the reveal lists exactly `options` in order with `display_name`, `description` when non-empty, and the capabilities hint when present — fast/auto/effort levels as small dim tags; a pick calls `SetModel{workspace, model: option.model}` echoing the served `AgentModel` verbatim; disabled in flight; refusal at the button; the new selection arrives by push), the PERMISSION-MODE PICKER (`src/topbar/permission-mode.ts`, `drawTopbarPermissionModePicker`): the model selector's sibling — the button shows `current.display_name`, the reveal lists exactly `options` (display_name), a pick calls `SetPermissionMode{workspace, mode: option.mode}` echoing the served spelling, disabled in flight, refusal at the button, the new mode arrives by push; `drawTopbarContextChip` (the figure as a YELLOW number; hover/click reveals `drawTokenBreakdownView`: sections with headings, rows with label, tokens (format with thousands separators only — the figure is a count), share as "NN.N%" from `share_permille` only when set, `emphasized` rows bold/unindented, `depth` indent; `.list-rows` delimiters); `drawTopbarWarningStrip` (NOTHING drawn on an empty list; otherwise the warning chip "⚠ N" — the count of entries in the served list is display of the list length, drawn as the chip's badge; the first-level reveal lists `line.text` per warning newest-first with delimiters; clicking a row opens the second-level detail overlay by arm: accounting lines; unmodeled tool name + argument lines (or the name alone); detached unmodeled name + a ticking clock from `started_at_ms`; session fault component + detail; degraded window component + reason + "since <age>" ticking while `open`, or "<began>–<ended>, N observations dropped" when `closed`; a back affordance returns to the list).

3. `src/login/link.ts` — `interface LoginLink { attach(signal: AbortSignal): AsyncIterable<LoginTerminalOutput>; sendKeystrokes(data: Uint8Array): Promise<void>; sendResize(rows: number, cols: number): Promise<void> }` and `connectLoginLink(ctx): LoginLink`: `attach` consumes `client.watchLoginTerminal({workspace}, {signal})` directly (a SERVER stream that CONCLUDES with the `closed` frame — a legitimate producer end, so do not use the standing-stream helper's reconnect; strict-check each frame with `assertNoUnknownFields`); the two sends are `callUnary(client.sendLoginInput({workspace, input: {case: "keystrokes", value: {data}}}))` / `(… resize{rows, cols})`; a `SendLoginInputError` (empty) renders in the overlay header as a refusal and is logged.

4. `src/login/login.ts` — `mountLoginOverlay(host, ctx)`: `open()` → `OpenLogin{workspace}` (per-account idempotent — a second open joins) → success `config_dir` shown in the overlay header → show the overlay full-screen (port the legacy xterm-style look), create the xterm terminal + fit addon, attach the link, write every `bytes` frame to the terminal (scrollback replays first), forward keystrokes (`onData` → `sendKeystrokes(utf8 bytes)`) and resizes (`sendResize(rows, cols)` on fit/window resize), and on the `closed` terminal frame close the overlay (the account chip updates on its own push — nothing to re-probe: log that). The close button calls `CloseLogin{workspace}` then closes the overlay (closing an absent login is success). Refusals (`OpenLoginError`/`CloseLoginError` — empty today) render in the overlay header as `.refusal[data-arm]`; a link transport failure is reported via `ctx.failures.report(controlPlaneFailed{what: "login terminal", cause})`. Escape does NOT close (the TUI needs it) — only the button.

5. Validation, logging, CSS in delimited `/* ---- topbar (src/topbar) ---- */` and `/* ---- login overlay (src/login) ---- */` sections; reuse the existing topbar/login classes; thin grey delimiters via `.list-rows`.
